# AI_USAGE.md

## What I used AI for
- Understanding what each part of the assignment was actually asking for,
  and breaking a large spec into a step-by-step plan.
- Getting starter code for the corpus-download script, the parameterized
  fertility functions, and the Part B capacity-math cells.
- Debugging: the FLORES gated-dataset/trust_remote_code error, and a
  Windows path bug (single-backslash string being misinterpreted as
  escape characters) that caused an OSError in Part B.
- Interpreting ablation output — e.g. explaining why the grapheme-chars
  ablation initially showed 0.00% change (denominator defaults to "word",
  so the char-counting fix was invisible until denominator="grapheme"
  was set explicitly).

## Where it helped most
- The Part B capacity math (KV cache bytes/token, the reported_tok_s
  formula) was checked against the real bench_log.csv row by row before
  I trusted it, rather than just being asserted.

## How I verified the work
- I re-ran every calculation myself, in my own notebooks. Part A and
  Part B were each rebuilt from scratch once in a fresh notebook, and
  the numbers reproduced exactly both times.
- I hit the Windows path error directly myself (pasted the real
  traceback) — that one wasn't anticipated by the original code and had
  to be diagnosed against my actual environment.
- I did not independently spot conceptual bugs in fertility.py beyond
  what AI initially flagged; my verification was running the ablations
  myself and confirming the measured deltas, not discovering the bugs
  from scratch.

## What I did NOT let AI do
- Final interpretation and reasoning in audit.md, A3_analysis.md,
  A4_memo.md, partB/answers.md, and partC/memo.md is based on numbers I
  personally generated by running the code myself. I can re-derive any
  of these numbers live.
